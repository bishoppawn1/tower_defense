# Project instructions

- Read `spec.md` before changing gameplay and keep it current when the game design changes.
- Keep the game playable as a static GitHub Pages site. Use relative asset paths and avoid requiring a server or build step unless the project changes to support one.
- Preserve existing gameplay and player controls unless the requested change calls for changing them.
- Verify changes with appropriate checks and, when possible, play through the affected behavior in a browser.
- After making and verifying changes, commit and push them to the GitHub repository. Check the working tree and remote state first, and preserve other people's work. Report any failures or unverified behavior.
